How Osmosis judges recall

Per-question strength (0–1)

Unseen ideas start at 0.08. After a response, the accuracy estimate is updated as 65% previous score + 35% latest result (correct = 1, incorrect = 0). An idea's current strength then combines that estimate with time decay and a response-speed factor:

strength = (0.18 + 0.72 × accuracy) × exp(−days / (2 + 18 × accuracy)) × speed

Speed is 18 seconds ÷ average response time, clamped between 0.55 and 1.0. The average time uses 70% prior average + 30% latest time. Strength is clamped to 0.03–0.99. This is a simple heuristic, not a validated memory model.

How the next batch is chosen

Unseen ideas get priority 3.3. Seen ideas are ranked by weakness (1 − strength) plus a small overdue bonus (up to 0.5). Up to the chosen known-mix percentage is replaced with randomly selected strong ideas. One parent idea can appear only once per run; one alternate wording is selected randomly if that parent has variants. Misses lower the stored score of seen neighbors by 0.025 when they share a topic or keyword. Runs never delete questions or history.

Clock and saved data

Progress is saved to this browser's localStorage after answers and settings changes. Each response stores a Unix timestamp from the device clock (Date.now), so elapsed days are recalculated when you reopen the app; no background timer is needed. Changing the device clock can affect the estimate. A paused break is excluded from response time. Browser storage is local to this browser/profile and can be cleared by browser settings; use Export JSON for a backup.

How the next run is picked

Weak and overdue ideas lead the queue. New ideas get coverage before anything is considered mastered. Roughly 20% of a mixed run revisits strong ideas, while variants are sampled under a single parent idea so duplicates never appear in one run.
